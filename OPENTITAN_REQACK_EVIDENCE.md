Pin: OpenTitan `7a3ad34b6d483f4d1d69ac670ddb1c45f1172e19`, generic
`prim_flop`, `prim_flop_2sync`, and `prim_sync_reqack`. EnRzHs=0/1 selects NRZ/RZ;
EnRstChks remains its default zero. The source declares different reset contracts
for these protocols. Neither contract is proved by this structural pilot.

The source-level oracle is
[the pinned module](https://github.com/lowRISC/opentitan/blob/7a3ad34b6d483f4d1d69ac670ddb1c45f1172e19/hw/ip/prim/rtl/prim_sync_reqack.sv):
NRZ launches src_req_q and dst_ack_q into req_sync and ack_sync respectively;
RZ launches the corresponding FSM state bits. Each crosses into u_sync_1.d_i
in the other clock domain. The runner requires exactly these two crossing
identities and both endpoint locations, not unstable autogenerated cell names.
Native Yosys and slang provide different frontend implementations for the NRZ
comparison, but share synthesis passes; this is not an independent CDC engine.

These are synthesis configurations: each frontend's default SYNTHESIS definition
selects upstream dummy assertion macros; SIMULATION is absent, so randomized CDC
delay modeling is absent. This is recorded, not an assertion-enabled or simulation
pass. No macro/RTL edits, annotation injection or diagnostic suppression is used.
Raw frontend failures, source/header inventory hashes, exact commands, statuses
and timings are archived in the requested output directory. Header inventory is
not claimed to be a complete observed dependency closure. Current development
artifacts are under `../evidence/cdc-opentitan-reqack/`.

Signal aliases and source annotations improve reviewability; they do not prove
handshake correctness, reset release, metastability containment, FIFO behavior,
reconvergence safety or full CDC qualification. Module names never imply safety.
The production roadmap still requires pinned Linux tooling, protocol proofs,
independent CDC comparison and the full clock/reset configuration matrix.
